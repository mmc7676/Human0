The Maxey0 Context Plane

Harnessing a six-level embedding field of work (topics, concepts, skills, agents and MCP servers) for agent execution

Mike Cohan (Human0) · Claude: Co-Author, Co-Research Engineer · November 2026 · 21 pages

Download PDFOpen full screen

Summary

Agent systems built on MCP can reach thousands of tools, and most systems treat choosing among them as retrieval. The paper argues the real decision is larger and has structure: what kind of work a task is, which specialist performs it, who checks it, and which servers each should hold. That structure should be built, versioned and served as a context plane, separate from the execution plane that acts on it. The Maxey0 Context Plane places every task on one fixed-depth path, Domain → Topic → Concept → Skill → Agents (primary, checker, support) → MCP servers, over 11 domains, 128 topics, 711 concepts, 1,998 skills, 1,021 agents and 117 real MCP servers, each with a vector in one shared space. An observer lens reads each level from the nodes selected above it and records drift. A dense bge-m3 signal mixed with TF-IDF raises exact-skill recovery from labels from 93.3% to 98.7% on the live server. The plane is served by a public read-only MCP server, drawn as an interactive 3D graph that runs inside Claude, and stated in OWL 2 with SHACL validation.

Questions and answers

What problem does it address?
Choosing what should handle a task (kind of work, specialist, checker, tools) as a structured decision, not a flat tool-retrieval step.
What is the core structure?
One fixed-depth path per task: Domain → Topic → Concept → Skill → Agents (primary, checker, support) → MCP servers, every node embedded in one shared space.
What is measured?
Exact-skill recovery from labels on the live server: 93.3% with TF-IDF alone, 98.7% with the dense bge-m3 signal mixed in.
What does it not claim?
Routes are candidate paths, not authorizations; concepts, skills and agents are generated hypotheses that are structurally checked, not curated knowledge.
Where can I try it?
In the app at /app, or inside Claude as a custom connector (see the home page).
