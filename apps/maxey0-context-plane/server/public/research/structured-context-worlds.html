Summary

As agents combine models with persistent context, tools, code execution, sandboxes and other agents, the problem shifts from controlling model outputs to controlling the execution space where behavior happens. The paper introduces Structured Context Worlds (SCWs): bounded, addressable execution spaces that bind context, execution identity, capabilities, resources, tool and protocol access, provenance, admission rules and permitted transitions. SCW0 is the supervisory layer that creates and manages SCWs, routes context and capabilities between them, evaluates boundary transitions and records provenance. SCWs sit between agent harnesses and operating-system sandboxes rather than replacing either. It is an architecture proposal; no empirical result is claimed.

Questions and answers

What is an SCW?
A bounded semantic and contextual execution space for an agent or task, binding its context, identity, capabilities, tool access, provenance and allowed transitions into one addressable unit.
What is SCW0?
The supervisory control layer that creates SCWs, routes context and capabilities between them, evaluates boundary transitions and records provenance.
Does it replace sandboxes?
No. A sandbox restricts processes, files, network and compute; an SCW is the semantic boundary through which those capabilities are organized and governed.
What evidence is there?
None claimed. The paper gives the model, threat model, evaluation method and a falsifiable research agenda.
